二. XML 文件格式

XML 是一种数据保存和交换的文件格式。在深度学习中，XML 常用于标记目标位置和精确度；在 HMI 中，常见配置文件也常采用 XML 格式。

2.1 XML 的组成

2.1.1 XML 声明

XML 第一行通常是声明，包含以下属性：

  • version：说明当前 XML 文件版本号，必选。
  • encoding：说明当前 XML 文档使用的字符编码集，可选，默认是 UTF-8。
  • standalone：说明当前 XML 文档是否为独立文档，可选，默认是 yes。

2.2 XML 的语法

2.2.1 XML 元素命名规则

  • 名称可以包含字母、数字以及其他字符；
  • 名称不能以数字或标点符号开始；
  • 名称不能以 xml、XML、Xml 等字符开始；
  • 名称不能包含空格；
  • 可以使用任意名称，没有保留字；
  • 所有对象都区分大小写。

2.2.4 CDATA

CDATA 中的所有文本不会被 XML 处理器解释，而会直接显示。CDATA 段中出现 <、>、"、'、& 时，无需使用转义字符。

第三章：JSON 文件格式

JSON 是一种基于文本的数据交换格式，源于 JavaScript 语言，但设计目标是独立于语言。

目前几乎所有主流编程语言都支持 JSON。它常用于数据存储和网络传输，例如 VSCode 工程项目中的配置文件。

JSON 由两种基本数据结构组成：

  • 对象：键值对集合；
  • 数组：有序值集合。

3.1 JSON 语法

3.1.1 对象

对象使用花括号 {} 表示，内部是多个键值对集合。

3.1.2 数组

数组使用方括号 [] 表示，内部是按顺序排列的多个值。

3.1.3 键值对

键值对由键和值组成，键必须是字符串，值可以是任意合法 JSON 类型。

3.1.4 数据类型

JSON 常见数据类型包括：

数据类型 示例
字符串 String "Hello World"
数字 Number 42、3.14
布尔值 Boolean true、false
数组 Array [1, 2, 3]
对象 Object {"key": "value"}
空值 null null

3.2 VSCode 的 JSON 配置

VSCode 一个工程通常包含 tasks.json 和 launch.json 两个配置文件。

3.2.1 tasks.json

tasks.json 用于自动化构建任务，包含编译、运行环境等配置。

字段说明：

  • label：任务名称，可以更改，但不建议频繁改。
  • type：任务类型，shell 表示先打开 shell 再输入命令。
  • command：执行命令，这里是 gcc。
  • args：传给编译命令的一系列参数。
  • group：任务分组。
  • presentation：任务执行时的终端显示设置。
  • problemMatcher：捕捉编译器报错信息，并显示到 VSCode 的“问题”面板。
  • dependsOn：任务依赖。例如运行前必须先构建。

3.2.2 launch.json

launch.json 用于调试程序，包含调试器、程序入口等配置信息。

字段说明：

  • name：调试配置名称。
  • type：调试类型，cppdbg 对应 C/C++ 调试插件。
  • request：请求配置类型，可为 launch 或 attach。
  • program：要调试的程序路径。
  • args：调试时传递给程序的命令行参数。
  • stopAtEntry：是否在程序入口暂停。
  • cwd：调试工作目录。
  • externalConsole：是否使用外部控制台。
  • MIMode：指定调试器类型，这里是 gdb。
  • miDebuggerPath：指定 gdb.exe 路径，需要根据自己的 MinGW 安装位置修改。
  • preLaunchTask：调试前执行的构建任务，需与 tasks.json 中的 label 对应。
